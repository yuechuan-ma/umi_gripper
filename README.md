# 总线舵机夹爪控制

这是一个用于控制一到两个总线舵机夹爪的 Python 项目。它支持两个舵机共用一个串口，也支持每个舵机各自使用一个串口。

项目提供以下功能：

- 通过标定记录夹爪的闭合、中立、张开位置；
- 用 `0.0` 到 `1.0` 表示夹爪开度；
- 在后台持续读取位置、负载、电流和温度；
- 发现夹爪在闭合方向夹住物体后保持夹持，在张开方向碰到限位后停止施力；
- 可分别设置两个通道的速度、夹紧力度和状态更新频率；
- 提供舵机 ID 核对与修改工具。

## 使用前准备

### 硬件条件

- 使用兼容 ST / SC 协议的 TTL 总线舵机，例如 STS3215 或 ST3215；
- 驱动板与舵机之间通过 DVG 三线连接：`D` 为信号，`V` 为电源正极，`G` 为地；
- 驱动板的跳线拨到 `B`，驱动板与电脑之间通过USB-C连接；
- 驱动板电源电压必须符合**舵机**本身的规格（7.4V舵机使用7.4V电源，12V舵机使用12V电源）。不要把不同额定电压的舵机接到同一驱动板上。

> 标定和夹紧测试会带动夹爪运动。开始前请确认机构没有碰撞风险，也不要把手放在夹爪行程内。

### 安装依赖

推荐使用 Python 3.10。在项目目录执行：

```powershell
pip install -r requirement.txt
```

Linux 下串口通常需要当前用户拥有访问权限；如无法打开 `/dev/ttyACM*` 或 `/dev/ttyUSB*`，请先处理系统的串口权限。

## 第一次使用：标定

配置文件 [`gripper_config.json`](gripper_config.json) 初始状态中两个通道都是空的。首次使用请运行：

```powershell
python gripper_cal.py
```

程序会执行以下步骤：

1. 扫描可用串口和舵机 ID；
2. 分别选择 0 号、1 号通道所用的舵机。任一通道均可选“本通道为空”；
4. 对每个已选择的通道，依次用 `W` / `S` 标定闭合位置、中立位置、张开位置，按回车确认；
5. 选择是否进行夹紧力度测试；
6. 自动把结果写入 `gripper_config.json`。

若希望在标定时每 0.5 秒显示位置、负载、电流和当前状态，请使用：

```powershell
python gripper_cal.py --log
```

## 夹紧力度测试

三点标定后，程序会询问是否进入可选的夹紧力度测试。

1. 夹爪会先张开；
2. 放入测试物后按回车，夹爪自动闭合；
3. 感受夹持效果：按 `W` 将力度增加 5，按 `S` 将力度减少 5；
4. 每次调整后夹爪会重新张开，放入测试物并按回车再次测试；
5. 满意后按回车保存，或按 `Q` 跳过。

力度范围为 1 到 100。这个值同时决定舵机允许使用的最大夹持力度；数值越大，夹持力越大。

## 修改或核对舵机 ID

运行：

```powershell
python gripper_id.py
```

该工具可扫描并显示舵机的串口、ID、通信速度和版本编号，也可修改 ID。

修改 ID 时，同一串口上只应连接待修改的那一个舵机。若两颗舵机原本 ID 相同，它们会同时响应修改命令，无法用软件将它们区分开。

## 快速交互测试

完成标定后，运行：

```powershell
python quickstart.py
```

按提示输入“开度 通道号”，例如：

```text
0.8 0
```

其中 `0.0` 表示闭合，`1.0` 表示张开；第二个数字为通道号 `0` 或 `1`。输入 `q` 退出。

## 在自己的程序中使用

创建 `Gripper` 时会自动打开所需串口并启动后台状态更新。使用完成后必须调用 `disconnect()` 关闭串口。

```python
from gripper import Gripper

gripper = Gripper()
try:
    gripper.goto(0.8, 0)          # 0 号通道张开到 80%
    result = gripper.wait(channel=0)
    print(result["state"])
    print(gripper.get_width(0))   # 读取当前开度

    gripper.reset(0)              # 回到标定的中立位置
finally:
    gripper.disconnect()
```

若只配置了一个舵机，也可以省略通道号：

```python
gripper.goto(0.8)
width = gripper.get_width()
```

也兼容下面的写法；离开代码块时会自动断开：

```python
from gripper import Gripper

with Gripper() as gripper:
    gripper.goto(0.8, 0)
    gripper.wait(channel=0)
```

常用方法如下：

| 方法 | 作用 |
| --- | --- |
| `goto(开度, 通道号)` | 设定目标开度，开度范围为 0 到 1。 |
| `get_width(通道号)` | 返回当前实际开度。 |
| `get_state(通道号)` | 返回位置、负载、电流、温度与当前状态。 |
| `wait(timeout, 通道号)` | 等待本次运动结束并返回状态。 |
| `reset(通道号)` | 回到标定的中立位置。 |
| `disconnect()` | 停止后台更新并关闭串口。 |

当配置了两个通道时，调用 `goto()`、`get_width()` 等方法必须明确给出通道号。调用未配置的通道会直接报错。

## 运行状态说明

`get_state()` 返回的内容包含 `state`、`message`、`width` 和 `telemetry` 等信息。常见状态如下：

| 状态 | 含义 |
| --- | --- |
| `就绪` | 当前没有运动命令。 |
| `运动中` | 正在前往目标位置。 |
| `已到位` | 已到达目标位置附近。 |
| `已夹住` | 闭合方向检测到物体或硬限位，正在按设定力度保持。 |
| `已阻塞` | 张开方向检测到物体或硬限位，已停止继续施力。 |
| `异常` | 通信、位置有效性或温度等出现问题。 |

闭合方向和张开方向的处理不同：闭合时检测到不再移动，夹爪会保持当前夹紧力度；张开时检测到限位，则会停在当前位置，避免持续顶住机械限位。

## 配置文件

标定结果保存在 [`gripper_config.json`](gripper_config.json)。文件中固定有两个位置：`servos[0]` 和 `servos[1]`。不使用的通道保持为 `null`。

每个已配置通道的常用项如下：

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `serial_port` | 串口名，例如 Windows 的 `COM3` 或 Linux 的 `/dev/ttyACM0`。 | 标定时写入 |
| `servo_id` | 舵机 ID。 | 标定时写入 |
| `baudrate` | 通信速度。 | 标定时写入 |
| `closed_position_steps` | 闭合位置。 | 标定时写入 |
| `neutral_position_steps` | 中立位置，用于 `reset()`。 | 标定时写入 |
| `open_position_steps` | 张开位置。 | 标定时写入 |
| `speed` | 运动速度，范围 1 到 3400。 | 1200 |
| `grip_strength` | 夹紧力度，范围 1 到 100。 | 50 |
| `status_frequency_hz` | 后台读取状态的频率，范围 1 到 100。 | 50 |
| `calibration_step_steps` | 标定时每次按 W/S 的移动步长。 | 128 |
| `motion_timeout_s` | `wait()` 的默认超时时间，单位为秒。 | 30 |

可以在断开夹爪后手动修改速度、力度等设置。请不要手动修改标定位置、串口、ID 或通信速度，除非你明确知道改动后的硬件状态；更换舵机、安装位置或 ID 后，应重新标定。

同一串口上的两颗舵机必须使用不同 ID，并使用相同通信速度。两个舵机可共用一个物理串口，程序会只打开一次该串口。

## 常见问题

### 找不到舵机或无法打开串口

检查 USB 连接、驱动板跳线是否在 `B`、舵机供电、DVG 接线方向和串口权限。扫描会优先尝试常用的 1,000,000 通信速度，找不到时才依次尝试其他速度，因此在非默认速度下会更慢一些。

### 报“当前位置无效”

当前读到的位置超出了已标定的闭合与张开范围。通常是安装位置被手动移动、更换了舵机、端点标得过紧，或标定确认后舵机还有少量移动。请确认硬件状态，必要时重新标定，并在两个端点预留余量。

### 为什么要调用 `disconnect()`

夹爪对象会持续占用串口并在后台读取状态。对于普通写法，程序结束使用夹爪后应调用 `disconnect()`；使用 `with Gripper() as gripper:` 时会自动完成这一步。
